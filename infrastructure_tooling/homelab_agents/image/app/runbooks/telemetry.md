# Telemetry stopped: a host, a log source, or Falco

Three detections: a host that sent metrics in the last 24 hours went quiet for 15 minutes; one log feed (k3s or Vault audit, k3s container logs, a host's journald, the UniFi syslog, the AdGuard query log) went silent past its limit while its host is still up; or Falco stopped on a host that is still reporting. Usual causes: the VM was shut down or rebooted (Proxmox shows it stopped), the OTel collector or Falco stopped or crashed, a Cribl route or the network/Tailscale path broke, or a service was restarted during maintenance. An attacker turning off auditing, Falco or telemetry looks the same.

Check `| mstats latest(proxmox_vm_uptime) where index=metrics earliest=-1h by name` for the VM's state, whether logs from the host (`index=infra host=<host>`) stopped at the same time or only metrics did, the last journald lines before it went quiet (shutdown, otelcol errors, OOM), and whether it has come back. For one log source: whether other sourcetypes from the same host and index still arrive (`| tstats max(_time) where index=<index> by sourcetype host`), and whether the service that writes it was restarted or reconfigured (a Vault audit device change, an Argo CD sync, a Cribl change). For Falco: its journald lines on the host before it stopped (`index=infra host=<host> falco`), and whether a `systemctl stop` or upgrade in the Tailscale SSH or sudo commands explains it.

Skills: if the VM is up but its data stopped (or only one source did), invoke `forwarder-and-data-ingest-doctor`; if Cribl or the collector logs HEC errors, `hec-setup-and-troubleshooting`.
